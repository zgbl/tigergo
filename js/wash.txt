
## 4. 完整的后端API接口要求
### 4.1 数据库设计
Collection: testQuestions

```
// MongoDB文档结构
{
  _id: ObjectId,
  id: String, // 唯一标识: 
  sgfHash_moveNumber
  sgfHash: String, // 关联的SGF文件哈希
  sgfFilename: String, // SGF文件名
  moveNumber: Number, // 步数
  boardState: [[String]], // 19x19棋盘状态
  数组，值为'black'|'white'|null
  currentPlayer: String, // 当前下棋方 
  'black' | 'white'
  candidatePoints: [{
    type: String, // 'actual' | 'best' | 
    'alternate'
    position: String, // SGF格式位置 如 
    'Q16'
    row: Number, // 行坐标 0-18
    col: Number, // 列坐标 0-18
    winRate: Number, // 胜率
    description: String // 描述
  }],
  correctAnswer: {
    position: String, // SGF格式位置
    winRate: Number, // 胜率
    explanation: String // 解释
  },
  winRateLoss: Number, // 胜率损失
  difficulty: String, // 难度 'easy' | 
  'medium' | 'hard'
  questionText: String, // 题目文本
  createdAt: Date, // 创建时间
  updatedAt: Date // 更新时间
}
```
索引设计：

```
// 创建索引
db.testQuestions.createIndex({ "sgfHash": 
1 })
db.testQuestions.createIndex({ 
"difficulty": 1 })
db.testQuestions.createIndex({ 
"moveNumber": 1 })
db.testQuestions.createIndex({ 
"createdAt": -1 })
db.testQuestions.createIndex({ "id": 1 }, 
{ unique: true })
```

### 4.3 后端实现要点
1. 1.
   数据验证：
   
   - 验证棋盘状态数组格式（19x19）
   - 验证候选点坐标范围（0-18）
   - 验证胜率范围（0-100）
   - 验证难度枚举值
2. 2.
   去重处理：
   
   - 使用唯一索引防止重复插入
   - 提供upsert选项更新已存在的测试题
3. 3.
   性能优化：
   
   - 使用批量插入操作
   - 合理的分页大小限制
   - 数据库索引优化
4. 4.
   错误处理：
   
   - 统一的错误响应格式
   - 详细的错误日志记录
   - 数据库连接异常处理
5. 5.
   安全考虑：
   
   - 输入参数验证和清理
   - 防止NoSQL注入
   - 请求频率限制
